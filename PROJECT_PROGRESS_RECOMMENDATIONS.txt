Recommended options to track progress (short descriptions + quick start):

1) Lightweight Markdown/TODO files (fast, local)
- Create TODO lists: `TODO.md` / `IN_PROGRESS.md` / `DONE.md` in the repo root.
- Use `- [ ]` and `- [x]` task list syntax. Good for minimal overhead and quick capture.

2) Git-based tracking (integrates with workflow)
- Use clear branch names and commit messages; add `CHANGELOG.md` for release notes.
- Use GitHub Issues & Projects (if repo hosted) to track tasks, assign, label, and link commits.

3) Small CLI tracker (recommended first build)
- Single-file Python CLI (`src/progress.py`) backed by `progress.json` or SQLite (`progress.db`).
- Commands: `add`, `list`, `start`, `complete`, `remove`, `export`.
- Pros: lightweight, versioned with code, easy to extend into CI hooks or snapshot commits.
- Quick start: `python src/progress.py add "Write docs"` and `python src/progress.py list`.

4) Simple web dashboard (Flask / FastAPI)
- Build `src/progress_app.py` + SQLite; provide Kanban views and export.
- Pros: visual and shareable. Cons: heavier dependencies and runtime.

5) Hybrid approach (file + script + remote board)
- Keep `progress.json` in repo; sync with GitHub Issues or Trello via a small sync script.
- Use a daily snapshot script that commits `progress_summary.md` to the repo for historical trace.
